# dsh-im-indicator

**给 DSH 会话列表加一个极简的 IM 通道指示器：哪个会话正被飞书/微信驱动、它现在在回答还是已完成。**

- 胶囊只出现在**通道当前绑定的那一条**会话上；状态点对**所有会话**生效（桌面端直接对话也会绿/橙）
- 🟢 绿色呼吸 = 正在回答；🟠 橙色 = 有未读回复；空闲 = 什么都不显示
- 标的是**通道当前绑定的那一条**，不是整个工作区

## 为什么说它轻

| | |
|---|---|
| 依赖 | **0 个**（不引任何第三方包） |
| 打包体积 | **7.0 kB**（解包 15.7 kB，7 个文件） |
| 宿主代码 | 74 行：一条只读路由 |
| 客户端代码 | 202 行：一个插槽、一个共享轮询、一个胶囊 |
| 网络 | 每 5 秒一次 60 字节的本地 GET，页面隐藏时停 |
| 宿主状态 | 不缓存、不建表、不写盘 |

对比同类实现：不打标整个工作区、不做通知、不做菜单、不建数据库——只回答一个问题：**这条会话现在被谁占着。**

## 配合谁使用

- 飞书通道 [`dsh-channel-feishu`](https://github.com/Poy-Coder/dsh-channel-feishu)（npm 同名）
- 微信通道 [`dsh-channel-wechat-ilink`](https://github.com/Poy-Coder/dsh-channel-wechat-ilink)（npm 同名）

两个都装也可以，胶囊按各自的绑定会话区分。

## 安装

```bash
dsh plugin add dsh-im-indicator
```

宿主半边新增一条路由，**装完重启一次 DSH**；之后只改外观的话刷新页面即可。

## 它怎么知道“当前绑定”

通道插件把当前会话写在自己的状态文件里：

```
~/.dsh/feishu-channel-state.json → { "sessionId": "session-…" }
~/.dsh/wechat-channel-state.json → { "sessionId": "session-…" }
```

本插件把它们通过只读路由暴露给页面：

```
GET /im-indicator/bound
{ "v": 1, "bound": { "feishu": "session-…", "wechat": "" }, "at": 1794817824743 }
```

页面每 5 秒拉一次，只在 id 变化时重绘。

## 鉴权

`webServer` 的具名路由在任何 Host/Origin 检查之前应答，所以这条路由**自己**调用 DSH 的 `ctx.connection.requestRejection({ headers })`：

| 情况 | 结果 |
|---|---|
| 请求通过 DSH 的 Host/Origin 与浏览器登录检查 | `200` + 载荷 |
| 检查拒绝（跨站 Origin、非法 Host、无有效会话） | `401`/`403`，**空响应体，不含任何会话 id** |
| 检查本身抛错 | `403`（失败关闭，宁可空白也不泄露） |
| 运行环境没有 `connection` 服务 | 正常返回（该环境没有浏览器载体可鉴权） |

## 稳定性

| 风险 | 处理 |
|---|---|
| 状态文件缺失或损坏 | 视为空绑定，绝不抛错（有测试钉住） |
| 页面切到后台 | 轮询暂停，回到前台立即刷新一次 |
| 接口失败 | 指数退避 5→10→20→40→60 秒，保留上次结果 |
| 响应格式变化 | 带 `v` 版本号，不认识的版本直接忽略 |
| DSH 客户端 API 变化 | 状态 hook 特性检测，拿不到就只显示胶囊 |
| 卸载 | 定时器、监听器、样式元素随插件销毁 |

## 限制

- 依赖通道状态文件的 `sessionId` 字段，字段改名需要同步更新；
- 只认 `feishu` / `wechat`，新增通道需要加一行映射；
- 圆点来自 DSH 的会话状态，不代表“通道连接是否健康”（这一层可以后续再加）。
